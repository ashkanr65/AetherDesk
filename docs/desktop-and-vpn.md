# Desktop display, SFTP and app-only WireGuard

Fullscreen sends the current monitor arrangement to the host and refreshes it when monitors change. Returning to the tab restores the latest tab dimensions; switching between one and all monitors updates the host layout without disconnecting the session. Each local monitor displays its matching area; differing sizes and offsets are preserved within the 16384-pixel/32-megapixel desktop limit. The fullscreen menu can be dragged by its hamburger handle and docks to the top, bottom, left or right edge of the screen.

The bundled Xwayland 24.1.10 includes `tools/xwayland-monitors.patch`. It exposes a separate connected RandR output and CRTC for each monitor. Applications therefore see actual monitor geometry, including when rearranging monitors without changing the total canvas. The host window manager and its own decorations remain in use. A system Xwayland without the patch cannot provide this multi-monitor behavior; use the matching agent bundle.

The compositor paces rendering to its configured refresh rate, retains the Pixman target for damage tracking and publishes only changed frames. Both raw-frame handoffs retain only the newest full image. On decoder overload, the client keeps the last complete image, skips dependent encoded frames until a fresh keyframe arrives, and reports overload to the host's bitrate/frame-rate controller. Input and control continue while video falls behind. The host's encoded backlog is limited to two frames. These reduce avoidable work and stale frames; they do not establish a performance comparison with X2Go on a particular host.

Updated clients also acknowledge fully received encoded frames. Once this feedback is active, the host permits at most two unacknowledged frames across the entire transport, including SSH and kernel buffers. If video output falls behind while waiting, it skips stale queued video and resumes at a fresh keyframe. Receipt delays above the observed minimum round-trip time feed the rate controller; receipt handling does not wait for file/clipboard operations. Older peers retain their previous behavior without a protocol-version change. Rebuild both client and agent, then end/recreate a retained desktop to run the updated host code.

SFTP Upload opens the local file chooser. Select a remote file and use Download, or use the download action on its row, to choose a save location. Folder navigation, selection and transfer history survive resizing and hiding the explorer. Transfers currently operate on files; navigate into folders to transfer their contents.

## WireGuard

In a connection profile choose **Import .conf**. AetherDesk saves the selected file's path, like an SSH key path. Keep that file available and protect it as you would a private key. Its private keys are not copied into the saved profile or logs. Remove it from the profile with **Disable WireGuard**.

The imported configuration must have one Interface and one Peer, Address, PrivateKey, PublicKey, AllowedIPs and Endpoint. IPv4, IPv6, PresharedKey and PersistentKeepalive are supported. MTU defaults to 1380; supported values are 1280–1420. DNS entries must be IP addresses reachable through AllowedIPs. For private hostnames, DNS queries run inside the tunnel. Endpoint hostname resolution uses the local resolver to locate the VPN peer. Configurations with executable hooks are rejected; no scripts run. ListenPort, Table and SaveConfig do not apply because there is no system interface.

A saved config can serve multiple simultaneous connections, including repeated opens of the same profile. Each connection has its own TCP socket, source port, bounded buffers and cancellation. Matching profiles share one process-local WireGuard peer and virtual stack, since independent tunnels with the same peer identity would compete for its roaming endpoint. Different peer identities have separate tunnels. Conflicting settings for an already-active identity fail explicitly rather than silently changing its routes or keys.

Only the session's SSH connections use WireGuard. X11 and remote-desktop sessions open two independently authenticated SSH connections: terminal/control/input use the interactive connection, while X11 graphics or desktop video use the graphics connection. Separate SSH channels alone cannot provide this isolation because a full channel queue can block the shared SSH packet reader. Both connections retain host-key verification and the configured VPN restrictions. SFTP uses the interactive connection. No system VPN adapter, route or listening proxy is installed. Destinations outside AllowedIPs fail without falling back to a direct connection. Disconnect closes the session's sockets and resources; other sessions continue, and the peer tunnel stops after the final connection closes. The retained host desktop continues working. Microphone and camera forwarding are not implemented or enabled.

## Regression checks

Linux checks include idle-frame suppression, latest-frame selection, distinct monitor CRTCs with mixed sizes/offsets, host window-manager maximize/resize behavior, session resume, video decode, OpenSSH SFTP transfer/resume, and encrypted WireGuard TCP plus tunneled DNS and cancellation. Native Windows tests verify fullscreen return restores the remote resolution once and releases keyboard hooks and window resources. Flutter tests cover the file chooser, selection and transfer state across layout changes. Full Windows application builds run in GitHub Actions.
